# P5 clean-genesis evidence

These AC21, AC22, and M6 reports were generated by:

```sh
python3 scripts/validate_origin_orbis_genesis.py \
  --origin-node target/release/origin \
  --orbis-node target/release/origin-orbis \
  --compact-wasm target/orbis-metadata/release/wbuild/origin-orbis-runtime/origin_orbis_runtime.compact.wasm \
  --write-evidence
```

The validator constructs each raw chain spec twice from exact checked-in candidate inputs and checks
byte-for-byte determinism. It derives the Orbis state root and header hash from the SCALE genesis
header; verifies the binary, embedded runtime code, compact Wasm and metadata identities; decodes
FRAME Twox128 raw-storage prefixes; and rejects non-default domain records or old-network
dependencies. The Origin raw-storage digest is the deterministic relay genesis identity recorded
until the final launch envelope is signed.

`pass` means the clean-genesis tooling and candidate invariants are executable. It is deliberately
not a production-launch approval: each report says `candidate_only: true`,
`production_activation: false`, and `approval_status: PENDING`. Production public keys, final state
identities, reproducible WASM hashes, and runtime/security/release-owner signatures must replace the
candidate material during the launch ceremony.
