# SDK View Audit (Nov 11, 2025)

Goal: capture the current shape of the SDK view layer before refactoring it to rely exclusively on `cord-primitives` DTOs and generated Subxt bindings (no manual `scale_value` usage).

## Findings

- `cord-subxt-sdk/src/query/{entity,register,token}.rs` construct SCALE payloads with `scale_value::Value` (`ArgBuilder`, `authorization_value`, helper functions) and decode the `Result<Vec<u8>, Vec<u8>>` envelope by hand.
- Helper crates (`src/types/*`, `src/scale/*`, `src/query/dynamic.rs`) re-implement runtime schemas to keep those dynamic calls working, which causes drift every time pallets add a new field or view.
- `primitives/cord` already exports many response DTOs (`RegistryInfoView`, `DevPacketSnapshot`, `InfoAttributeHistoryEntry`, etc.), but it does **not** offer a single module enumerating every view request/response pair or a shared error taxonomy for clients.

## Gaps To Close

1. **Request DTOs** – introduce a `cord_primitives::view_api::{entity,register,token}` module containing request structs (deriving `Encode`, `Decode`, `TypeInfo`, `MaxEncodedLen`) that mirror each view’s arguments. Serde derives must be behind the `std` feature.
2. **Response Completeness** – audit existing DTOs and add any missing ones (e.g., entity info bytes debug payload etc.) so SDK never defines its own view response structs.
3. **Shared Errors** – create a `cord_primitives::view_api::AuthorizationError` enum (AuthFailed, Expired, Replay, InvalidContext, InvalidRequest, PermissionDenied, NotFound) which pallets can emit and the SDK surfaces verbatim.
4. **Typed Subxt Integration** – refactor `cord-subxt-sdk` queries to consume `runtime::apis::views` generated by Subxt using the new DTOs, deleting `scale_value`, `query::dynamic`, `ArgBuilder`, and the bespoke decoder helpers.
5. **Docs & Tests** – document the contract in `docs/` and add round-trip tests for every request/response DTO to guarantee SCALE stability.

This checklist drives the subsequent implementation steps.
